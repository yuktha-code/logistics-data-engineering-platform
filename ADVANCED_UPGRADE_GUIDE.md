# MongoDB + PySpark upgrade — Last-Mile Logistics Data Platform

**Purpose:** Extend the original Python/SQL ETL with a real MongoDB raw-event mirror, a real PySpark transformation, Parquet output, and an independent Airflow DAG. Source data are **synthetic** by default. Nothing in this project is affiliated with Porter or handles Porter's customer data.

## Evidence status (12 October 2026)

- **Completed and locally verified:** all 18 offline tests passed; 130-order SQL smoke run processed 502 unique events; replay inserted zero orders/events. Source-stage CLI `generate` and `validate` also ran successfully.
- **Implemented but NOT executed here:** actual MongoDB bulk writes, PySpark runtime, Parquet serialization and the Airflow advanced Docker stack. This execution environment lacks a MongoDB server, PySpark and Docker. An isolated GitHub Actions job is included, but it has **not** run until this code is uploaded and the workflow executes.
- **Not implemented:** real Azure Blob deployment, a running Hadoop/Hive cluster, an independently measured distributed-scale benchmark, Kafka-based live streaming ingestion and production alerting.
- **No GitHub changes made:** this ZIP is a local upgraded source snapshot. Publishing requires replacing or merging into your GitHub repository after verifying the changes.

## Architecture

```text
Synthetic CSV orders + tracking events
        |
        v
Schema / stable-key / relationship / temporal quality checks
        |
        +----> PySpark full-event duplicate check + join to orders
        |          |
        |          +----> city/month partitioned Parquet archive
        |          |
        |          +----> Spark-cleaned events CSV
        |
        +----> MongoDB tracking_events documents (_id = event_id)
                   |
                   v
             indexed order/time queries
        |
        v
Existing SQLAlchemy transactional loader consumes Spark-cleaned events CSV
        |
        v
staging tables -> 3 dimensions + 2 facts -> delivery SLA/driver/city marts
        |
        v
SQL/quality audits, summary JSON, HTML dashboard
```

MongoDB is **not** a replacement for the relational warehouse. It maintains a validated document representation with upserts; Spark performs the processing and the SQL warehouse remains the analytics store. Writes to MongoDB and SQL are independently replayable but **not** a distributed ACID transaction.

## On Windows — prerequisites

1. Install **Python 3.11**, **Java 17**, and **Docker Desktop** (Windows WSL 2 backend enabled).
2. Unzip this project. Open PowerShell inside the project folder (containing `run_advanced.py`).
3. Keep the original demo path usable without advanced dependencies.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-advanced.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe run_pipeline.py generate --orders 6000
```

### 1 — Real MongoDB with Docker

```powershell
docker compose up -d mongo
docker compose ps
# Mongo is bound to the host loopback address at port 27018
.\.venv\Scripts\python.exe run_advanced.py --skip-spark
.\.venv\Scripts\python.exe run_advanced.py --skip-spark
```

Look in `results/advanced_run.json`. The second run should insert 0 SQL orders/events, and Mongo should report `upserted: 0` (existing documents match). For development inspection:

```powershell
docker compose exec mongo mongosh --quiet --eval 'db.getSiblingDB("logistics_dev").tracking_events.countDocuments({})'
```

**Security:** MongoDB authentication is disabled in this *localhost-only development demo*. Do not expose port 27018 to a public network or use it with sensitive or real customer data.

## Design tradeoffs and limits

- The existing Python source validator reads complete CSV batches into memory; not a streaming producer or fully distributed raw ingest.
- Source key conflicts are rejected before persistence; Spark also rejects unexpected conflicts. Exact duplicates are deduplicated without losing distinct events.
- Spark uses a local master (`local[2]`) by default. There are no observed scalability or production throughput claims.
- The MongoDB document mirror receives batch records via the Python driver, not Spark's distributed MongoDB connector. It is useful for basic NoSQL/document-store competence, not a proof of distributed MongoDB reads.
- The Parquet directory represents the most recent source snapshot and is replaced on each run; the SQL warehouse can retain past rows from earlier runs.
- The Airflow image and Docker stack have not been built in this environment. Confirm resource usage and container permissions before using them.
- SQL transactional load and MongoDB bulk upsert are individually idempotent, but no cross-store exactly-once or distributed-transaction guarantee exists.
- Always ensure repository authorship and contributions are represented accurately.
